# O2: prove you own your show with a description code

No migration. O1's `show_ownership_proofs` table (061, already live on `ldtmhafewfifdizgfrnn`) holds the code hash, expiry, counts, and statuses. This job does not write 091. It does not apply anything. Payouts are not wired.

## Flow

A signed-in show owner opens `/settings/ownership` from the Verify ownership card on `/settings`. The card is show accounts only.

1. The owner chooses a medium. Podcast uses `show_profiles.feed_url`. YouTube uses a channel URL or a bare `UC` id the owner pastes.
2. `POST /api/ownership/start` with `{ medium }` (and `channel` for YouTube) returns one code, `TAYLSLATE-` plus 6 characters. The plaintext is in that response only. The page shows it until the owner leaves. A later visit does not show it again.
3. The owner pastes the code into the RSS channel description or the notes of one of the latest 10 episodes, or into the YouTube channel description.
4. `POST /api/ownership/check` with an empty body reads the newest pending target and looks for the code. The body is ignored. The code is not sent back.
5. A hit sets that proof to `verified`, clears `code_hash`, sets `verified_at`, and sets `shows.ownership_status` to `verified`. The owner can delete the code after that.
6. Contested rows wait for O4. There is no public badge, no permanent link, and no "Advertise on this show" ask.

## State

| Status | What the owner sees |
| --- | --- |
| No proof | Start. Podcast shows the feed URL. YouTube asks for a channel URL. |
| `pending`, not expired | Check now. The code is on screen only right after start. |
| `verified` | Verified. |
| `contested` | Pending tag, and "Our team is reviewing this." |
| `expired`, or a pending code whose 7 days have passed | Start again. |

Pending is a tag, not a third value of `shows.ownership_status`. That column stays `unclaimed` or `verified`.

## Target

The owner does not pick a show. The server resolves it.

- Podcast target: `normalizeRssUrl(show_profiles.feed_url)`. No feed is 400, "Add your RSS feed to your show profile first."
- YouTube target: a bare id matching `/^UC[A-Za-z0-9_-]{22}$/`, or the same id after `youtube.com/channel/` or `m.youtube.com/channel/`. A handle or any other URL is 400, "Paste your channel URL that starts with youtube.com/channel/."
- Matching rows: `shows.rss_url` normalizes to the podcast target, or `shows.youtube_channel_id` equals the `UC` id. At most 5. Each gets its own pending proof and the same `code_hash`. None is 409, "We could not find this show in the catalog yet." No proof is written. The response and the page show the feed URL or channel id only. No show name and no show id.

A feed that matches more than one show verifies or goes to review one row at a time. Default from the job note: yes, up to 5.

## Code

Alphabet is `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (31 symbols: A-Z and 2-9, without 0, O, 1, I, or L). Six characters from `crypto.randomInt`. The stored value is the sha256 hex of the uppercase code. Comparison uses `timingSafeEqual`. The code expires 7 days after start. Starting again for the same target sets that user's older pending rows to `expired` and clears `code_hash`.

The check searches the decoded, tag-stripped text for an exact code and compares its hash. It does not need the plaintext back from the browser.

## Check results

- Hit, and the show has no verified proof and no approved exclusive rep who is someone else: `verified`. `code_hash` is cleared. `shows.ownership_status` becomes `verified`.
- Hit, and the show already has a verified proof, or an approved exclusive `agent_show_relationships` row whose agent is not this user: `contested`, note `needs_admin_review`. The owner sees "We passed this to our team to review." A unique-index race (`23505`) takes the same path.
- Miss: `miss_count` goes up. "Not found yet. Feeds can take a while to update."
- The 5th miss: `contested`, same review sentence.
- `code_expires_at` has passed: `expired`, `code_hash` null, same review sentence. The page then offers start again.
- YouTube with no API key, or a failed channels.list call: no miss. "We could not check YouTube right now. Try again later." If the key is missing, the page says "YouTube checks are not available yet."
- A feed URL the SSRF guard blocks (loopback or a private address) counts as a miss. The response has no fetch detail.

Each check adds 1 to `check_count` and sets `last_checked_at`. `user_id` is always the session user. Another user's proof is not read or updated.

## Rate limits

Defined in `lib/ownership/check.ts` and enforced with `enforceRules`, fail closed.

| Bucket | Limit |
| --- | --- |
| `ownership_start_user_day` | 5 per user per day |
| `ownership_check_user_minute` | 1 per user per minute |
| `ownership_check_user_day` | 20 per user per day |

Over the limit is 429 with Retry-After. A limiter failure is 503 `{ "error": "unavailable" }`.

## Gate

Every route: session, or 401. Then `profiles.role` is `show` and a `show_profiles` row exists for `auth.uid()`, or 403. The page redirects to `/login?next=/settings/ownership`, and calls `notFound()` for anyone else. A request whose Origin is missing or is not the site origin is 403. `https://taylslate.com` is treated as `https://www.taylslate.com`.

Errors are fixed strings. Responses do not include database text, show ids, show names, hashes, or fetch errors. Logs are `[ownership]`, the Postgres error code, and the first 8 characters of the proof id.

## What a verified row unlocks

`getVerifiedProfileTies` treats a verified proof with a `show_profile_id` as a tie. `isPayoutOwnerVerified` is true when a verified proof ties that show to that profile. This job sets `show_profile_id` on every proof. Neither helper is called from `lib/payouts`. Wiring the payout gate is a separate job and needs Chris's OK.

O4 resolves `contested` rows. This job does not build that queue.

The daily rep heads-up is the existing `sweepOwnerVerificationNotices` cron. It already looks for a proof verified in the last 7 days. O2 does not call it and does not send email.

## YouTube quota

A YouTube check is one `channels.list` call, 1 unit, through `getYouTubeClientSafe` and `getChannelDetails`. The per-user limits cap how often that runs. These calls are not recorded on `youtube_quota_days`. That is a known gap. A connected YouTube OAuth channel is not ownership proof.

## Not in this job

No payout, Stripe, billing, or aircheck change. No discovery, booking, brand page, or show onboarding change. No admin queue. No email. No Vercel env change. No new table, policy, or grant.
