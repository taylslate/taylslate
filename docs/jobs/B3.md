## What shipped

`/admin/roster-requests` lists pending `agent_show_relationships`, oldest first. Each row shows the agent email, the show name, whether the show is discoverable, the source (`admin`, `import`, or `claim`), `is_exclusive`, and `created_at`. Conflict context is computed on read: other pending or approved links on that show, whether one of those is an approved exclusive and which agent holds it, and whether `shows.agent_id` differs from the link's agent. `exclusiveConflict` is true only when another approved exclusive link exists. Approving that row asks for a confirm. Approving any other pending row does not.

Approve calls `approveRosterLink`. That helper is unchanged. A link that is not pending returns "Not pending" and writes nothing. Discoverable flips only when `shows.agent_id` equals the link's agent.

Reject requires a note of 1 to 500 characters. The update sets `status` to `rejected`, `review_note`, `rejected_by`, and `rejected_at` where `status` is `pending`. It does not write `public.shows`. An approved or rejected row is left as it is.

The page and both routes check `isShowsAdmin` on the server. A signed-out or non-admin visit to the page is a 404. A signed-out route call is 401. A signed-in non-admin route call is 403.

Ownership proof is omitted. `lib/ownership` does not exist on this branch, and this job does not import it.

The screen is not in the sidebar. `lib/nav/items.ts` is outside this job. Open `/admin/roster-requests` while signed in as a shows admin.

## Migration 067

`supabase/migrations/067_roster_link_review_note.sql` adds nullable `review_note`, `rejected_by`, and `rejected_at` on `agent_show_relationships`. `rejected_by` references `profiles(id)` on delete set null. `review_note` is null or 1 to 500 characters. The file does not update or delete rows. It re-asserts `service_role` select, insert, update, and delete. It does not grant anon, public, or authenticated. RLS stays enabled. No new policy.

Throwaway Postgres 16, migrations 001 through 067, then 067 a second time. `auth.uid()`, `auth.users`, and `storage.objects` were stubbed. `show_claims` and `outcomes` were stubbed the same way as the 060 suite.

`information_schema.role_table_grants` for `public.agent_show_relationships` after that second paste:

| grantee | privilege_type |
| --- | --- |
| authenticated | SELECT |
| service_role | DELETE |
| service_role | INSERT |
| service_role | SELECT |
| service_role | UPDATE |

anon: no rows. PUBLIC: no rows. That is the same authenticated and service_role set 065 left in place (055's select for authenticated, 020's four service_role privileges, 055 and 065 revoking the rest).

A 500-character note stores. A 501-character note fails the check and leaves the stored note unchanged. The show's `is_discoverable` stays at its default. Reject does not write `shows`.
