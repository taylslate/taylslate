# M1: MCP tool layer over the public API v1

No migration. Nothing in this job is applied to a live database.

## What shipped

`POST /api/v1/mcp` is a stateless MCP endpoint. The body is one JSON-RPC 2.0 message. The response is one JSON object, or `202` with an empty body for a notification. There is no SSE stream and no session id.

The server speaks protocol `2026-07-28`, `2025-11-25`, and `2025-06-18`. `2026-07-28` uses `server/discover`. The 2025 versions use `initialize`. All three versions support `ping`, `tools/list`, and `tools/call`. Capabilities advertise tools only. `serverInfo.name` is `taylslate`.

Auth is the same bearer key as `/api/v1` (`Authorization: Bearer ts_live_<prefix>_<secret>`). A missing, malformed, revoked, or untied key is `401` with `WWW-Authenticate: Bearer`. The per-key limit is 60 POSTs per UTC minute. A foreign `Origin` is `403`. A body over 64 KB is `413`. A body that is not JSON is `415`. `GET`, `PUT`, `PATCH`, and `DELETE` are `405` with `Allow: POST`.

`tools/list` returns only the tools the key's scopes allow. `tools/call` on a tool the key cannot use is a tool error, `API key lacks the required scope.`, and reads no row. Read tools call the existing v1 read functions. `propose_campaign` calls `recordCampaignCreate`. `propose_outreach` calls `recordOutreachDraft`. Both only insert a pending `api_write_actions` row. Nothing is sent, created, signed, or charged.

`callTool(ctx, name, args)` is the in-process entry the command agent will use. It applies the same scope check and argument checks. The HTTP route uses it too.

## Access

No new table. `api_keys` and `api_write_actions` keep the grants from migrations 057 and 070. This job does not change them.

## Known gaps

- The command agent has no `api_keys` row. `api_write_actions.api_key_id` is `NOT NULL`, and `recordCampaignCreate` / `recordOutreachDraft` require a uuid key id. The command agent job needs its own migration before it can record a pending action in process.
- No OAuth, no dynamic client registration, and no protected-resource metadata.
- No approve, send, sign, charge, or pay tool.
- `tools/list` is one page. A non-empty cursor is invalid params.
- Show tools use the same tied-show projection as `GET /api/v1/shows`. Contact and rates are present only when `fullShowIdsForCaller` includes the show.
