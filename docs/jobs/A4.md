## What shipped

`/settings/agent-actions` lists the signed-in brand's `api_write_actions` rows. Tabs are Pending, Approved, Rejected, and Expired. The brand approves or rejects a pending row once, with an optional note. The actor is the session user id. `profiles.role` is read by that id and must be `brand`.

`GET /api/settings/agent-actions` returns an allowlist: id, kind, status, created_at, decided_at, decision_note, executed_at, result_campaign_id, execution_error, the key name and prefix, and a summary built from the payload. `payload_hash`, `key_hash`, and `idempotency_key` are not returned. A pending row older than 14 days is shown as expired.

`POST /api/settings/agent-actions/{id}` takes `{ decision: "approve" | "reject" | "retry", note?: string }`. Unknown keys are 422. The Origin host must match the request host. The rate limit is 60 decisions per user per hour (`api_action_decide_user_hour`), and it fails closed.

Approving `campaign.create` creates one draft campaign with `createCampaign`: status `draft`, platforms podcast and youtube, recommendations empty, brief version 2. The name matches the manual brief name, with ` - ` in place of the em dash. A reused pattern must belong to the session user. Failure leaves the row approved, stores a generic `execution_error`, and returns 502. Retry uses the same claim and cannot create a second campaign while that claim holds.

Approving `outreach.draft` confirms the show with `getShow`. The decision is recorded. Nothing is sent. The screen says "Approved. Nothing was sent."

## Access

`api_write_actions` stays RLS-on with zero policies. 082 re-asserts `service_role` all privileges and revokes `anon`, `public`, and `authenticated`, including `truncate`, `references`, and `trigger` on `authenticated`. Every read and write filters `brand_id` to the session user.
