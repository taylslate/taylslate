## Queue

`GET /api/admin/ownership` and `/admin/ownership`.

A row is in the queue when its status is `contested`, or its status is `expired` and the same user has no newer proof for that show. Oldest first. Limit 100. Optional `?status=contested` or `?status=expired`. The scan reads the oldest 1000 candidates, then applies the newer-proof rule, then keeps 100.

Each row shows the show name, method (`rss_code`, `youtube_code`, or `admin`), target, the requester's login email from `getAuthEmail`, `miss_count`, `last_checked_at`, `created_at`, the reason (`note`), and whether an approved exclusive `agent_show_relationships` row exists, with `rosterRepLabel`. Responses do not include `code_hash` or `show_profile_id`.

## State

| Status | Who sees it | What they see |
| --- | --- | --- |
| No proof | Owner | Start. The manual review form is available. |
| `pending`, not expired | Owner | Check now. O2 copy. The manual review form is available. |
| `verified` | Owner | Verified, including when an admin approved a `method` `admin` row. |
| `contested` | Owner | Pending tag, and "Our team is reviewing this." |
| `contested` | Admin queue | In review, with the note. |
| `expired`, and no newer proof for that user and show | Owner | Start again. |
| `expired`, and no newer proof for that user and show | Admin queue | Expired, with the note. |
| `expired`, and a newer proof exists for that user and show | Admin queue | Hidden. |
| `rejected` | Owner | "Not verified", the `decision_note`, and Start again. |

Pending is still a tag. `shows.ownership_status` stays `unclaimed` or `verified`.

## Detail

`GET /api/admin/ownership/[id]`. The id is checked with `isUuid`. A bad id is 400 "Bad request." An unknown id is 404 "Not found".

The detail adds the show name, `rss_url`, `youtube_channel_id`, and `ownership_status`, the other proofs for that show (status, method, `created_at`, `decided_at`, and `decided_by` as the admin's login email), and every `agent_show_relationships` row (rep label, status, `is_exclusive`). When any link is exclusive, the page says "Review the rep link in roster requests."

## Decisions

Approve, `POST { action: "approve" }`:

1. Guarded update: `.eq("id", id).in("status", ["contested", "expired"])` sets `status` `verified`, `decided_by` to the session admin user id, `decided_at` and `verified_at` to now, `code_hash` null, and `updated_at` now.
2. Zero rows is 409 "Already decided", unless that proof is already `verified` and `decided_by` is set. That is the admin approve path. A retry then runs steps 3 and 4 again. A verified proof with no `decided_by` (the O2 code path) stays 409 and changes nothing. A unique-index violation (`23505`) is 409 "This show already has a verified owner." Nothing else is written.
3. `shows.ownership_status` becomes `verified` for that show.
4. Other `pending`, `contested`, or `expired` proofs for that show become `rejected`, with `decision_note` "Another owner was verified.", `decided_by`, and `decided_at`.

`agent_show_relationships` is never written. The rep link stays. The show stays bookable through the rep.

If step 3 or 4 fails, the response is 500 "Couldn't approve that proof." The log is the error code and `[ownership-admin]` only. The guarded update is the source of truth. Approving that same proof again finishes the show update and the sibling rejection. If that retry still returns 500, repair by hand:

- If the proof is `verified` and the show is still `unclaimed`, set `shows.ownership_status` to `verified` for that `show_id`.
- If other `pending`, `contested`, or `expired` proofs remain for that show, set them to `rejected` with `decision_note` "Another owner was verified.", `decided_by` the same admin user id, and `decided_at` now.

Reject, `POST { action: "reject", reason }`:

- `reason` goes through `rosterReviewNote` (1 to 500 characters). Otherwise 400 "A reason of 1 to 500 characters is required."
- The same guarded status filter sets `status` `rejected`, `decision_note` to the reason, `decided_by`, `decided_at`, and `updated_at`. Zero rows is 409 "Already decided".
- `shows.ownership_status` is unchanged.

Decisions are final. There is no undo route. The owner can start a new proof in O2. `decided_by` is always the session admin's user id, never a body field, and never an email.

## decision_note

O2 uses `note` for why a row reached review (`needs_admin_review`, or the owner's manual explanation). The admin's reason is a second fact. Writing it into `note` would erase the first. `decision_note` is nullable text, 1 to 500 characters when set. The owner reads it through the existing authenticated SELECT and the RLS policy. That is intended.

A missing column on the admin routes is 503 "Ownership review needs migration 091." Apply 091 before this deploy. The owner page retries the O2 select on 42703 or PGRST204 and still renders, with no decision reason, until the column exists.

## Manual request

`POST /api/ownership/manual` uses O2's show-owner gate and same-origin check. Body: `medium`, `explanation` (20 to 1000 characters), optional `link` (https only, at most 300 characters, stored as text, never fetched). YouTube also takes `channel`, the same string O2's start accepts, because the merged code resolves a YouTube target with `parseYoutubeChannelTarget` and the spec's `link` is evidence, not the target.

Shows come from `matchingShowIds(medium, target)`. No match is 409 "We could not find this show in the catalog yet." One proof is inserted per matching show with `method` `admin`, `status` `contested`, `show_profile_id`, `target`, and note `Manual review: ${explanation}` plus ` Link: ${link}` when a link is given. If the user already has a contested proof for one of those shows, the response is 409 "Your request is already with our team." and nothing is inserted.

Rate limit bucket `ownership_manual_user_day`, 3 per day, fail closed. Success copy is "We passed this to our team to review."

The owner page shows "Ask for manual review" when the user has no verified proof and no contested proof.

## Admin page

`/admin/ownership` is a server component. `notFound()` unless `isShowsAdmin(user.id)`, the same gate as roster requests. Signed out is `notFound()` here because `proxy.ts` already redirects to login. The API returns 401 and 403.

The page has the list, the filter, a detail panel, Approve, and Reject with a reason. States: empty ("No proofs need review."), list, detail, decided ("Verified." or "Not verified."), and an error line. It is reachable by URL only. The `/admin` page and the nav were not edited.

## Routes

Every O4 route:

- Auth, then `isShowsAdmin` on the admin routes. The manual route uses the owner gate.
- `enforceRules` with `failureMode: "closed"`. `admin_ownership_read_minute` is 60 per minute per admin on the GETs. `admin_ownership_decide_minute` is 20 per minute per admin on POST. `ownership_manual_user_day` is 3 per day on the manual route.
- Admin POST checks `requestIsSameOrigin`, the same check as the owner routes. A missing or cross-site Origin is 403. GET does not.
- POST bodies are capped at 8 KB (413) and require `Content-Type: application/json` (415).
- `Cache-Control: no-store` on every response, including errors and rate-limit responses.
- Error bodies are fixed strings. Logs are a route tag and an error code.

Writes go through `supabaseAdmin`.
