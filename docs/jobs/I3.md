# I3: Past-campaign import review and confirm

No migration in this job. Nothing here is applied to the database.

## What shipped

A brand-side screen at `/imports/past-campaigns`. The signed-in brand uploads a CSV, XLSX, or PDF, edits the parsed rows, chooses pooling consent, and confirms. Confirm posts to the existing save API. Discard resets the screen before that post. There is no discard endpoint.

The CRM index header links to this screen. That is the only change to an existing screen.

## Flow

1. Upload posts the file to `POST /api/deals/import?mode=past_campaign`. A parse error is shown as the API returned it.
2. Review is an editable table: show name, flight start, flight end, placement, price type, price, episodes, spend, conversions, and downloads. A row can be removed. A catalog suggestion is advisory text. The save body always sends `matched_show_id: null`. This screen does not write `shows`.
3. Consent is a checkbox, off by default. Copy: "Allow a later anonymized pool for this file." Terms version `pooling-v1` is sent only when the box is checked.
4. Confirm builds the body in `lib/imports/review.ts` and posts it once to `POST /api/imports/past-campaigns`. The confirmed step shows the record count from the response.

The session user id is the only `brand_id` the screen sends. The save API ignores that field and stamps the session brand itself.

## Plan gate

Import is not plan gated. Free, Starter, Operator, and the legacy agency plan can open the screen when the role is brand or agency. Show and agent accounts are sent to `/dashboard`, the same redirect `/crm` uses. A missing session goes to `/login`. A missing role goes to `/onboarding`.

Import should stay open to every brand-side account, including Free. The learning feed reads confirmed imports, and Free is the entry plan. CRM stays plan gated. This job does not add a gate.

The CRM link lives on the unlocked CRM header, so a Free brand does not see it. They can open `/imports/past-campaigns` directly.

## Grants

This job creates no table and changes no grants. Live `information_schema.role_table_grants` for the two tables the existing save API writes (queried, not altered):

- `past_campaign_imports` and `past_campaign_records`: `anon` and `public` have no privileges. `authenticated` has select, insert, update, and delete only. `service_role` also has references, trigger, and truncate. `postgres` holds the owner set.

The new read is `shows` (`id`, `name`) for the advisory label, through the signed-in server client, same lookup shape as the save route. `shows` already grants `anon` and `authenticated` broad privileges. This job does not change that.

Throwaway Postgres is N/A. No migration was added.

## Tests

`lib/imports/review.test.ts` and `app/(dashboard)/imports/past-campaigns/import-review.test.tsx`.

Covers draft-to-body mapping, an invalid price blocked, consent defaulting to false, a removed row left out, the upload / review / consent / confirmed steps, the advisory label, one save call, and the session brand id on that call.
