## What shipped

`POST /api/v1/campaigns` (`write:campaigns`) and `POST /api/v1/outreach` (`write:outreach`) validate a body and insert one `api_write_actions` row. The response is `202` with `{ action_id, status: "pending" }`. The same `Idempotency-Key` and payload hash returns that row with `200`. The same key with a different payload returns `409`.

Nothing is executed. These routes do not insert or update campaigns, deals, outreach, shows, or `agent_show_relationships`. They do not send email and they do not charge.

`GET /api/v1/actions` and `GET /api/v1/actions/{id}` require `read` and return only the calling brand's rows. Another brand's id is `404`.

A show on the outreach draft must be discoverable, or owned by the brand through a deal (`deals.brand_id` or a `brand_profiles` row for that user). Otherwise the response is `404`.

`withApiWrite` uses the same key resolution and per-key rate limit as reads, then the named scope. `Idempotency-Key` must be 1 to 128 printable ASCII characters. A JSON body over 64 KB is `413`. A non-JSON body is `415`.

## Access

`api_write_actions` has RLS enabled and no policies. `service_role` is granted all privileges. `anon`, `public`, and `authenticated` are revoked, including `truncate`, `references`, and `trigger` on `authenticated`.

## Known gaps

- No approve or reject path. Status stays `pending` until a later job.
- A reused campaign pattern id is checked as a uuid. It is not loaded, so ownership of that pattern is not checked until something executes the action.
- `api_key_id` does not cascade when a key row is deleted. Deleting the profile still cascades the action through `brand_id`.
- The campaign payload has no derived name. The manual brief route builds that name when it creates the row. This route only records the brief fields.
