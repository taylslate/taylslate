## What shipped

Two ownership states, `unclaimed` (the default) and `verified`, on `shows.ownership_status`. Pending is a tag, not a third state. There is no public verified badge, and brand-facing UI does not show the state. Every show stays findable and bookable. Discovery, scoring, booking, and visibility are unchanged.

`public.show_ownership_proofs` holds the checks O2 and O4 will write. This job does not write proof rows. A verified row ties `show_id` to `show_profile_id`. `podscan_id` is not a column and is not a tie. `code_hash` is sha256. The plaintext code is never stored. One verified proof per show.

`getVerifiedProfileTies` has a third branch. A verified proof is a tie. Pending, rejected, contested, and expired proofs are not. A verified proof with no `show_profile_id` is not.

`getOwnershipState` returns `{ state, pending }` per show. `pending` is true when a proof is pending or an `agent_show_relationships` row is pending. The labels `Verified`, `Unclaimed`, and `Pending` are exported for owner and admin views. Nothing renders them.

`isPayoutOwnerVerified` is true only when a verified proof ties that show to that profile. It is not called from `lib/payouts`. Wiring it before the first payout is a separate job.

`shows.is_claimed` stays. The column comment marks it deprecated. The three production writers that forced it true now pass false, which matches `createShow`'s default (`requested.is_claimed ?? false`):

- `lib/data/queries.ts` `importShows`
- `app/(dashboard)/shows/shows-client.tsx` `buildShowFromForm` (add and edit)
- `lib/data/show-surfaces.ts` `resolveOwnerShowId`

The Shows form does not render `is_claimed`. The edit path looks the same.

`show_claims` is dropped at the end of 061, after a guard that raises if the table has any rows. The check is inside `to_regclass('public.show_claims')`, so a rerun after the drop still succeeds.

One policy: `Owners read own ownership proofs`, select, `to authenticated`, `using (user_id = auth.uid())`. Anon select is permission denied. Authenticated insert is permission denied. Authenticated select returns only that user's proofs. A second verified proof for the same show fails the partial unique index. `ownership_status` `pending` fails the check.
