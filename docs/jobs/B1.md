# B1: bulk roster import API for reps

No migration. The next free number is 072, and this job did not need it. Nothing was written to `ldtmhafewfifdizgfrnn`. The grant query below is a read. Screenshots are not applicable. This is an API. No page or component was added.

## What shipped

`POST /api/reps/roster/import` previews or commits a rep's show list.

`mode` defaults to `preview`. `mode=commit` is the write. Any other value is 400. The agent id comes from `requireAgent`. A body, query, or header agent id is ignored. A signed-out call is 401. A signed-in non-agent is 403.

The body is JSON or CSV text, at most 500 data rows and 1 MB (1,048,576 bytes). JSON accepts a `rows` array, a `shows` array, or a bare array. CSV needs a header row. Columns are `name`, `platform` (`podcast` or `youtube`), `rss_url`, `apple_url`, `youtube_channel_id` (a `UC` id or a `youtube.com/channel/UC...` URL), `contact_email`, and `is_exclusive` (default true). `confirm` is the name-match flag. `podscan_id`, `agent_id`, `is_claimed`, `ownership_status`, and `is_discoverable` on a row are ignored.

Matching reads `shows` and `agent_show_relationships` through `supabaseAdmin`, in this order:

1. Exact normalized `rss_url` (case, `http`/`https`, and a trailing slash).
2. `shows.youtube_channel_id`, only when the input is already a `UC` id. A `/channel/UC...` URL counts. A handle does not. There is no YouTube API call.
3. An Apple id parsed from `apple_url`, compared only with `shows.apple_id`.
4. One normalized show name, the same key as migration 068. This is a suggestion. Commit links it only when the row sets `confirm`. A hidden show owned by another agent is not a name candidate and does not make a catalog name ambiguous.

`show_profiles` is not read. `podscan_id` is not a match field.

Each row is one of `new_show`, `link_existing`, `already_on_roster`, `exclusive_conflict`, or `invalid`. `already_on_roster` is any existing link for this agent, including pending and rejected. `exclusive_conflict` means another agent has an approved exclusive link. The result sets `exclusive_conflict: true`. No extra column is written. A pending exclusive link held by someone else is not a conflict.

Preview writes nothing. Commit writes accepted rows only:

- `new_show` inserts through `supabaseAdmin`. `agent_id` is the caller. `is_discoverable` is false unless `isShowsAdmin` is true, in which case it is true. `is_exclusive` is not a shows column. `is_claimed` and `ownership_status` are omitted so the defaults stand.
- `link_existing` does not update `shows`.
- Every accepted row inserts `agent_show_relationships` with `status` `pending`, `source` `import`, and `is_exclusive` (default true).
- If that link insert fails, a show created in the same request is deleted.
- A second commit for the same agent and show inserts no duplicate link. `UNIQUE(agent_id, show_id)` already enforces that. A `23505` is treated as already on the roster.

Nothing here calls `approveRosterLink`. Approval stays on B3.

A match result carries `show_id` and `show_name` only. A hidden show owned by another agent is returned on a strong-id match and is not returned on a name. The response does not include that show's contact, feed, audience, or `podscan_id`.

## Rate limit

`lib/api/rate-limit.ts` does not fit this route. `enforceApiRateLimit` increments `api_rate_windows` for an `api_keys.id`. `key_id` references `api_keys(id)`. A session agent id is not an API key, so the call would fail the foreign key. No limiter was added. The 500-row and 1 MB caps are the bounds this route enforces.

## Known gaps

- No per-agent rate limit. See above.
- A name whose lookup returns 50 shows is treated as more than one match, so that row is not linked and is not created.
- A feed or Apple lookup that returns 1,000 rows fails the request instead of guessing.
- A name key whose letters are not a substring of the stored name can be missed (`ab-cd` versus a two-letter key). The comparison itself stays exact.
- An unconfirmed name match is not created as a new show. The row waits for `confirm`.
- YouTube `@handle` and `/c/` URLs are not resolved.
- No domain event is written. `importShows` does not write one either.
- Multipart file upload is not accepted. Send JSON or CSV text.
- The 403 copy is the existing `requireAgent` sentence, "Only agents can read this."
